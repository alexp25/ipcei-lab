# L7 - LPI2C - On-Board P3T1755 Temperature Sensor

**Read the P3T1755 temperature sensor every 500 ms**

---

| | |
|---|---|
| **Session** | I2C |
| **Peripheral** | `LPI2C0`, `P3T1755DP` |
| **Hardware** | FRDM-MCXA153, on-board P3T1755DP sensor, reference `U8` |

## Context and Motivation

FRDM-MCXA153 includes an NXP **P3T1755DP** temperature sensor, reference **U8**. The sensor is connected to the board's I3C-capable pins, but it can communicate in I2C-compatible mode. This lab uses `LPI2C0` and the MCUXpresso SDK.

The board manual may show address `0x90`. That is the 8-bit write address. Normal LPI2C APIs expect the 7-bit address:

```text
0x90 >> 1 = 0x48
```

## Objectives

By the end of the lab you should be able to:

1. Identify the real sensor pins and configure them in Config Tools.
2. Initialize `LPI2C0` safely with timeout handling.
3. Keep the P3T1755 driver separate from board-specific LPI2C code.
4. Read the temperature register.
5. Convert positive and negative raw temperatures correctly.
6. Print temperature every `500 ms`.
7. Keep `.mex`, generated files, and CMake aligned.

## Hardware Connection

| Signal | MCU pin | Mux function |
|---|---|---|
| SDA | `P0_16` | `LPI2C0_SDA`, `Alt2` |
| SCL | `P0_17` | `LPI2C0_SCL`, `Alt2` |

Use:

- input buffer enabled;
- open-drain enabled;
- pull-up enabled;
- fast slew rate;
- low drive strength.

Pull-ups are important. Without a stable idle-high bus, LPI2C may report `Busy` before the first transfer.

## Register Map

| Register | Address | Role |
|---|---:|---|
| Temperature | `0x00` | temperature value, two bytes |
| Configuration | `0x01` | sensor configuration |
| TLOW | `0x02` | low threshold |
| THIGH | `0x03` | high threshold |

The driver can read the Configuration register during initialization to verify sensor presence without changing power-on settings.

## I2C Transaction

Temperature read sequence:

```text
Device address: 0x48, 7-bit
Write: [0x00]       select Temperature register
Repeated START
Read:  [MSB, LSB]
STOP
```

Equivalent SDK transfer:

```c
transfer.slaveAddress = 0x48U;
transfer.direction = kLPI2C_Read;
transfer.subaddress = P3T1755_REG_TEMPERATURE;
transfer.subaddressSize = 1U;
transfer.data = data;
transfer.dataSize = 2U;
transfer.flags = kLPI2C_TransferDefaultFlag;
```

Use a timeout. If the transfer does not complete, call `LPI2C_MasterTransferAbort()` rather than waiting forever.

## Temperature Conversion

The temperature is a signed 12-bit two's-complement value, left-aligned in a 16-bit word. Resolution is:

```text
0.0625 C / LSB
```

```c
int16_t p3t1755_decode_raw(uint8_t msb, uint8_t lsb)
{
    int16_t raw = (int16_t)((((uint16_t)msb << 8U) |
                             (uint16_t)lsb) >> 4U);

    if ((raw & 0x0800) != 0)
    {
        raw |= (int16_t)0xF000;
    }

    return raw;
}

float p3t1755_raw_to_celsius(uint8_t msb, uint8_t lsb)
{
    return (float)p3t1755_decode_raw(msb, lsb) * 0.0625F;
}
```

Check values:

| 12-bit raw | Signed value | Temperature |
|---:|---:|---:|
| `0x190` | `400` | `25.0 C` |
| `0x000` | `0` | `0.0 C` |
| `0xE70` | `-400` | `-25.0 C` |

The shift is `4`, not `5`. This sensor uses 12 bits and `0.0625 C/LSB`.

### Reusable Sensor Driver

The P3T1755 driver should not call `LPI2C0` directly. It receives transport functions through a config structure:

```c
typedef struct
{
    void *busContext;
    p3t1755_read_transfer_t readTransfer;
    p3t1755_write_transfer_t writeTransfer;
    uint8_t deviceAddress;
    uint32_t timeout;
} p3t1755_config_t;
```

This makes the driver reusable with another I2C/I3C adapter.

### Board Adapter

The board adapter owns the LPI2C peripheral and its clock:

```c
CLOCK_SetClockDiv(kCLOCK_DivLPI2C0, 1U);
CLOCK_AttachClk(kFRO_HF_DIV_to_LPI2C0);

LPI2C_MasterGetDefaultConfig(&masterConfig);
masterConfig.baudRate_Hz = 100000U;
LPI2C_MasterInit(LPI2C0, &masterConfig, CLOCK_GetLpi2cClkFreq());
```

This local ownership is valid when LPI2C0 is not fully instantiated through the Peripherals tool.

## Bring-Up and Diagnostics

| Symptom | Interpretation | Fix |
|---|---|---|
| `0x90` used as address | 8-bit write address used incorrectly | use 7-bit `0x48` |
| `kStatus_LPI2C_Busy` | bus not idle | check open-drain and pull-ups |
| NAK | wrong address or bus mode | confirm `0x48` and pins |
| assert in clock code | clock/divider not ready | configure clock before `LPI2C_MasterInit()` |
| Config Tools deletes clock edits | edit was only in generated file | move ownership to board adapter or configure in tool |
| invalid `.mex` settings | manual XML identifier not accepted | use only GUI-supported settings |

Recommended order:

1. Confirm sensor address `0x48`.
2. Verify `P0_16/P0_17`, `Alt2`, open-drain and pull-up.
3. Confirm CMake compiles the generated files from the active project folder.
4. Configure clock before `LPI2C_MasterInit()`.
5. Start with `100 kHz`.
6. Use timeout; never wait forever for a missing sensor.
7. Run a clean build after **Update Code**.

## Common Pitfalls

- Use `0x48`, not `0x90`, with LPI2C APIs.
- Sensor pins are `P0_16/P0_17`.
- Open-drain without pull-up can leave the bus busy.
- Do not make permanent fixes only in generated files.
- Do not add unsupported clock settings manually to the `.mex` XML.
- The sensor driver should not depend directly on `LPI2C0` or `main.c`.
