# L7 - LPI2C - On-Board P3T1755 Temperature Sensor

**Configure `LPI2C0`, read the on-board `P3T1755DP`, and print the temperature on the console.**

---

| | |
|---|---|
| **Session** | I2C / LPI2C |
| **Peripheral** | `LPI2C0`, `P3T1755DP` |
| **Hardware** | FRDM-MCXA153, on-board temperature sensor `U8` |
| **Console** | `LPUART0`, 115200 baud |

## Context

The FRDM-MCXA153 board includes an NXP **P3T1755DP** temperature sensor. The sensor is connected to the MCU pins that can be used by `LPI2C0` in I2C-compatible mode:

| Signal | MCU pin | Function |
|---|---|---|
| SDA | `P0_16` | `LPI2C0_SDA`, `Alt2` |
| SCL | `P0_17` | `LPI2C0_SCL`, `Alt2` |

The board manual may show address `0x90`. That is the 8-bit write address. The MCUXpresso SDK LPI2C APIs expect the 7-bit address:

```text
0x90 >> 1 = 0x48
```

Use `0x48` in application code.

## Objectives

By the end of this lab you should be able to:

1. Configure `LPI2C0` in the MCUXpresso Peripherals tool.
2. Configure the `LPI2C0` clock in the Clocks tool.
3. Verify the P3T1755 connection from the board schematic.
4. Route `P0_16` and `P0_17` in the Pins tool.
5. Generate updated configuration code safely.
6. Add a small application-level temperature read.
7. Diagnose common I2C bring-up errors such as `kStatus_LPI2C_Busy`.

## Workflow Overview

The project setup has two parts:

1. Generated configuration owned by MCUXpresso Config Tools: pins, clocks, and `LPI2C0` initialization.
2. Application code owned by you: the sensor transaction, conversion, and printing.

Do not manually edit `.mex` or generated board files. Make pin, clock, and peripheral changes in Config Tools, then use **Update Code**.

## 1. Configure LPI2C0 In Peripherals

Open the project `.mex` file with MCUXpresso Config Tools and enable `LPI2C0` as a master.

![Configure LPI2C0 as a master peripheral](../img/lab_i2c_p3t1755/01-configure-lpi2c0-peripheral.png)

Use a simple master configuration:

| Setting | Value |
|---|---|
| Peripheral | `LPI2C0` |
| Mode | Master |
| Transfer mode | Blocking or polling-style transfer |
| Baud rate | `100000` Hz to start |
| Pin config | 2-pin open-drain |

`100 kHz` is a good bring-up speed. After the bus is stable, `400 kHz` is also reasonable for this sensor and board.

## 2. Configure The LPI2C0 Clock

Open the **Clocks** tool and enable a clock source for `LPI2C0`.

![Configure the LPI2C0 clock](../img/lab_i2c_p3t1755/02-configure-lpi2c0-clock.png)

Confirm that the generated clock output is active and has the frequency expected by the generated `LPI2C0` configuration.

![Check LPI2C0 clock details](../img/lab_i2c_p3t1755/03-lpi2c0-clock-details.png)

A typical generated configuration may expose:

```c
#define LPI2C0_CLOCK_FREQ 12000000UL
#define LPI2C0_PERIPHERAL LPI2C0
```

Use the generated clock macro when initializing or using the peripheral. Do not hard-code a different clock in application code unless the project intentionally owns LPI2C initialization outside Config Tools.

## 3. Check The Board Schematic

The P3T1755DP is the on-board temperature sensor. Use the schematic to confirm that the sensor is connected to the same signals you are configuring in the Pins tool.

![P3T1755 schematic connection](../img/lab_i2c_p3t1755/04-p3t1755-schematic.png)

Key facts for this board:

| Item | Value |
|---|---|
| Sensor | `P3T1755DP` |
| Board reference | `U8` |
| 7-bit I2C address | `0x48` |
| Temperature register | `0x00` |
| Temperature bytes | 2 bytes, MSB first |

## 4. Configure SDA And SCL Pins

Open the **Pins** tool and route:

- `P0_16` to `LPI2C0_SDA`, `Alt2`;
- `P0_17` to `LPI2C0_SCL`, `Alt2`.

![Configure P0_16 and P0_17 for LPI2C0](../img/lab_i2c_p3t1755/05-configure-sda-scl-pins.png)

For both pins, configure the electrical settings for an I2C bus:

- input buffer enabled;
- open-drain enabled;
- pull-up enabled;
- fast slew rate;
- low drive strength.

Pull-ups matter. If SDA or SCL is not idle-high, the SDK may return `kStatus_LPI2C_Busy` before the first transfer.

## 5. Update Generated Code

After the peripheral, clock, and pin settings are correct, use **Update Code**.

![Update generated configuration code](../img/lab_i2c_p3t1755/06-update-generated-code.png)

Review the proposed changes before accepting them. The generated files should remain in the active project folder and should match the files compiled by CMake.

The generated application startup should keep this shape:

```c
void BOARD_InitHardware(void)
{
    BOARD_InitPins();
    BOARD_BootClockFRO12M();
    BOARD_InitBootPeripherals();
}
```

The root application file should call `BOARD_InitHardware()` once at startup.

## 6. Minimal Application Code

The examples below are intentionally small. They are suitable when the goal is to read the sensor from the active root application C file, while Config Tools owns `LPI2C0` initialization.

### Constants

```c
#define P3T1755_I2C_ADDRESS 0x48U
#define P3T1755_REG_TEMP 0x00U
#define P3T1755_TEMP_SIZE 2U
```

### Read The Temperature Register

```c
static status_t P3T1755_ReadRaw(int16_t *tempQ4)
{
    uint8_t data[P3T1755_TEMP_SIZE];
    lpi2c_master_transfer_t transfer = {0};

    transfer.flags = kLPI2C_TransferDefaultFlag;
    transfer.slaveAddress = P3T1755_I2C_ADDRESS;
    transfer.direction = kLPI2C_Read;
    transfer.subaddress = P3T1755_REG_TEMP;
    transfer.subaddressSize = 1U;
    transfer.data = data;
    transfer.dataSize = sizeof(data);

    status_t status = LPI2C_MasterTransferBlocking(LPI2C0_PERIPHERAL, &transfer);
    if (status != kStatus_Success)
    {
        return status;
    }

    uint16_t word = ((uint16_t)data[0] << 8U) | data[1];
    int16_t raw12 = (int16_t)(word >> 4U);
    if ((raw12 & 0x0800) != 0)
    {
        raw12 |= (int16_t)0xF000;
    }

    *tempQ4 = raw12;
    return kStatus_Success;
}
```

`tempQ4` is a fixed-point Celsius value where one count is `0.0625 C`. For example, `400` means `25.0000 C`.

### Print Fixed-Point Celsius

```c
static void UART_WriteTempQ4(int16_t tempQ4)
{
    uint32_t value;

    if (tempQ4 < 0)
    {
        LPUART0_WriteString("-");
        value = (uint32_t)(-(int32_t)tempQ4);
    }
    else
    {
        value = (uint32_t)tempQ4;
    }

    LPUART0_WriteU32(value / 16U);
    LPUART0_WriteString(".");

    uint32_t frac = (value & 0x0FU) * 625U;
    if (frac < 1000U) { LPUART0_WriteString("0"); }
    if (frac < 100U)  { LPUART0_WriteString("0"); }
    if (frac < 10U)   { LPUART0_WriteString("0"); }
    LPUART0_WriteU32(frac);
    LPUART0_WriteString(" C");
}
```

### Use It In The Main Loop

Call the sensor read from the main loop, not from an interrupt handler.

```c
int16_t tempQ4 = 0;
status_t status = P3T1755_ReadRaw(&tempQ4);

if (status == kStatus_Success)
{
    LPUART0_WriteString("P3T1755=");
    UART_WriteTempQ4(tempQ4);
    LPUART0_WriteString("\r\n");
}
else
{
    LPUART0_WriteString("P3T1755 error=");
    LPUART0_WriteU32((uint32_t)status);
    LPUART0_WriteString("\r\n");
}
```

If the project already has a SysTick flag or timer event, use that existing timing source to decide when the main loop prints. Avoid blocking I2C reads inside `SysTick_Handler()`.

## Temperature Format

The temperature register is a signed 12-bit two's-complement value, left-aligned in a 16-bit word.

```text
resolution = 0.0625 C / LSB
```

Check values:

| Register bytes | Signed Q4 value | Temperature |
|---|---:|---:|
| `0x19 0x00` | `400` | `25.0000 C` |
| `0x00 0x00` | `0` | `0.0000 C` |
| `0xE7 0x00` | `-400` | `-25.0000 C` |

The shift is `4`, not `5`.

## Bring-Up Checklist

| Symptom | Likely cause | Fix |
|---|---|---|
| `ERR 900` / `kStatus_LPI2C_Busy` | SDA or SCL is not idle-high | Enable pull-ups and open-drain for `P0_16/P0_17`; check external board state |
| `kStatus_LPI2C_Nak` | Wrong address or sensor not responding | Use `0x48`, not `0x90`; verify pins and sensor power |
| Constant `0.0000 C` | Register read or decode bug | Read two bytes from register `0x00`; shift by 4 and sign-extend bit `0x0800` |
| Build cannot find LPI2C symbols | Missing SDK component | Enable the LPI2C driver in project configuration |
| Config Tools wants to delete unexpected files | Project metadata mismatch | Stop and inspect paths before accepting Update Code |

## Common Pitfalls

- Do not use `0x90` with `LPI2C_MasterTransferBlocking()`; use `0x48`.
- Do not leave SDA/SCL as input-buffer-only pins; configure pull-up and open-drain.
- Do not manually patch generated files as the permanent fix.
- Do not perform blocking I2C transfers inside interrupt handlers.
- Do not decode negative temperatures with a plain signed right shift of the 16-bit register word; sign-extend the 12-bit value.
